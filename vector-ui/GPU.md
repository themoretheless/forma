# Векторный GPU backend — первый рабочий срез

## Что уже работает

- Rust `display_list.rs` строит список геометрических команд из существующей
  `Scene`/`Template`. Native и WASM используют один код подготовки геометрии.
- `Rectangle`/`Border` вычисляются аналитически в шейдере. SVG-полигоны и
  контуры букв передаются как рёбра, не как растровые изображения.
- Края скруглений и rounded clip используют непрерывное SDF-покрытие шириной
  в один физический пиксель вместо четырёх бинарных проб. Внутренний край
  рамки сглаживается отдельно; внешнее покрытие не применяется дважды.
  Пути и текст пока сохраняют четыре пробы на пиксель.
- `text.rs` читает контуры TTF и аппроксимирует кривые с допуском 0.15 физического
  пикселя. Покрытие и winding fill выполняются на GPU. Отверстия букв сохраняются.
- Один `vector.wgsl`: native через wgpu/Metal, браузер через WebGPU. На других
  нативных платформах используются backend-ы wgpu; здесь проверен только Metal.
- Команды распределяются по тайлам 32×32 с сохранением painter order. Фрагмент
  не перебирает все буквы/пути сцены. Вложенные clip композируются как группы,
  а не как независимая обрезка каждого дочернего примитива.
- При анимации на GPU обновляются только 48 байт параметров цвета/viewport.
  Геометрия кэшируется; resize пересобирает индекс тайлов, но не буферы контуров.
  Новый текст/шаблон, scroll или DPI перестраивает соответствующую геометрию.
- Native предпочитает GPU, при недоступности — CPU fallback с причиной в журнале.
  `FORMA_RENDERER=cpu` принудительно включает прежний CPU-рендер.
- На macOS содержимое Metal-слоя закреплено в top-left без растягивания
  предыдущего drawable и без неявной анимации bounds/position. Параметры кадра
  берутся из фактического размера полученной surface texture. Фиксированные
  размеры `.ui` не должны зависеть от промежуточного размера окна при live resize.
  Дополнительно включён `presentsWithTransaction`: wgpu 29 учитывает его при
  получении drawable и синхронизирует показ с транзакцией Core Animation.
  На macOS resize-кадр рисуется непосредственно в `WindowEvent::Resized`,
  а не откладывается до следующего `RedrawRequested`. Одного top-left было
  недостаточно: асинхронный present оставлял вертикальные скачки слоя.
- Web-preview сначала может показать CPU-кадр, затем переключается на WebGPU.
  При отсутствии WebGPU/ошибке устройства работает CPU, причина видна в tooltip
  бейджа и MCP `vector_status.gpuFallbackReason`. `gpuStats.uploads` считает
  загрузки геометрии, `frames` — отправленные GPU-кадры.
- CPU→GPU не передаётся готовая RGBA-картинка интерфейса. CPU-растеризатор
  не вызывается для GPU-кадров. HTML/CSS пока остаются оболочкой дизайнера,
  фоном артборда и рамкой выделения.

Это **tile-based vector coverage**, а не тесселяция путей в треугольники.
Треугольник используется только для запуска fragment shader. Тесселяция,
stencil и glyph atlas могут быть альтернативами для более сложных сцен.

## Проверки

```sh
cargo test --offline --manifest-path vector-ui/Cargo.toml
cargo run --offline --manifest-path vector-ui/Cargo.toml --release --features gpu --example gpu_check
cargo run --offline --manifest-path vector-ui/Cargo.toml --release --features gpu --example gpu_bench
```

Оба GPU-примера принимают пути к snapshot.ui и раскрытому Button.ui. Они требуют
реального adapter: отсутствие GPU считается ошибкой, не успешным skipped-тестом.

`gpu_check` также проверяет больше восьми промежуточных оттенков на дуге,
чтобы обнаружить возврат к квантованному сглаживанию. CPU-эталон пока использует
прежнее покрытие, поэтому различия непосредственно на краях ожидаемы.
Приведённые ниже ошибки измерены до перехода скруглений на SDF-сглаживание.

`gpu_check` читает GPU-текстуру обратно только для тестирования и сравнивает
premultiplied-пиксели с CPU. На текущей ImageButton при DPI 1/2 средняя ошибка
менее 0.003/255, максимальная 1/255; при DPI 1.25 есть 6 каналов с расхождением
более 4/255 (максимум 23 на wgpu 29 / Metal, контуры на границе образца). В тесте вложенного clip,
прозрачности и scroll после согласования жёсткого viewport максимум 2/255.
Изображения близки, но битовая идентичность на всех устройствах не обещается.
Эти offscreen-проверки не проверяют синхронизацию оконного compositor: live resize
нужно дополнительно проверять в нативном окне.

Замер текущей ImageButton на Apple M5 / Metal, 30 кадров после прогрева:

| Framebuffer | CPU encode+submit | Submit + синхронное ожидание GPU |
|---|---:|---:|
| 800×400 | 0.088 мс | 4.580 мс |
| 3840×2160 | 0.170 мс | 7.913 мс |

Это не GPU timestamp и не полный frame time окна: ожидание включает драйвер
и синхронизацию, но не compositor/present. Геометрия за эти 30 кадров повторно
не загружается. Ускорение относительно CPU на любой сцене не гарантируется.

## Что НЕ завершено

- Раскрытие наследования/`override`, `match` и layout содержимого всё ещё
  находятся в `src/components.js`. Полного переноса компилятора `.ui` в Rust нет.
- Display list потребляет существующий ограниченный Frame/Button runtime;
  произвольного retained-дерева контролов, реактивного layout и Rust ViewModel нет.
- CPU эталон пока отдельный растеризатор, не интерпретатор нового display list.
- Нет новых вариантов Brush/градиентов, расширения SVG или сложного shaping текста.
- Нет глобального LRU-кэша геометрии, GPU-тесселяции и GPU-профайлера в Studio.

Следующий архитектурный этап: перенос нормализованного дерева/layout в Rust,
затем единая инвалидация layout/paint/composition и общий ресурсный кэш.
