# Типизированные формы и привязки

Генератор читает `.ui` и создаёт Rust-тип формы в каталоге сборки. Приложение
передаёт экземпляр ViewModel, подписывается на события и управляет контекстами
через этот тип. Код чтения полей проверяет Rust-компилятор: ошибка в имени поля,
типе контекста или типе значения не проходит сборку.

Готовый проект: [examples/binding-app](examples/binding-app). Из корня репозитория:

```sh
npm run example:bindings         # Проверка ввода, события и рендера без окна
npm run example:bindings:native  # Нативное окно; F2 переключает клиента
```

В окне можно изменить имя и город и нажать «Сохранить». Обработчик обновляет
строку состояния. Две записи сохраняют свои изменения при переключении F2.
Это отдельное приложение с настоящей Rust ViewModel, а не обработчик Studio.

## Разметка

```text
component CustomerForm {
    contextType: 'crate::CustomerVm';
    events: ['saveRequested'];
    Frame {
        width: 360;
        height: 180;
        TextField {
            key: 'nameInput';
            value <-> state.name;
        }
        Button {
            key: 'saveButton';
            text: 'Сохранить';
            disabled: state.busy;
            clicked -> events.saveRequested();
        }
    }
}
```

`contextType` задаёт тип, а экземпляр передаёт Rust-код. `events` явно объявляет
публичные события; опечатка в обращении к событию не создаёт новое событие молча.
`key` создаёт метод доступа: `nameInput` → `name_input()`. Ключ должен быть
допустимым Rust-идентификатором; конфликты с методами формы диагностируются.

## ViewModel и прикладной код

```rust
use forma::binding::Property;
use std::rc::Rc;

pub struct CustomerVm {
    pub name: Property<String>,
    pub busy: Property<bool>,
}

// customer_form.rs создаётся build.rs в OUT_DIR.
include!(concat!(env!("OUT_DIR"), "/customer_form.rs"));

fn create() -> Result<CustomerForm, String> {
    let customer = Rc::new(CustomerVm {
        name: Property::new("Анна".into()),
        busy: Property::new(false),
    });
    let form = CustomerForm::new(customer.clone())?;
    form.on_save_requested(|event| {
        println!("Сохраняем {}", event.context.name.get());
    });
    customer.name.set("Мария".into());
    Ok(form)
}
```

`Property<T>` хранит значение и уведомляет подписчиков при `set`. Отдельный
derive-макрос для уведомлений не требуется. Клонирование Property разделяет поле;
новый `Property::new` создаёт независимое поле. Две формы с одним `Rc<ViewModel>`
разделяют данные, но каждая владеет своим Runtime, фокусом, выделением и Undo.

Обработчик получает контекст контрола на момент вызова. Захватывать старую
ViewModel в замыкании не нужно. Повторная регистрация обработчика заменяет
предыдущий; `control.disconnect_clicked()` снимает его.

## Контексты и перепривязка

```rust
form.set_context(other_customer.clone())?;
form.name_input().set_context(customer.clone());
form.name_input().inherit_context();

// Явная ссылка на поле остаётся привязана к customer при смене контекста.
form.name_input().bind_value(customer.name.clone());

// Привязка по типизированному пути снова следует за контекстом контрола.
form.name_input().bind_value_path(|vm| vm.name.clone(), true);
```

Контекст наследуется от родителя. Локальное назначение сохраняется при смене
родительского; `inherit_context()` возвращает наследование актуального значения.
Для вложенных объектов используется `Context<T>`:

```rust
pub struct AddressVm { pub city: Property<String> }
pub struct CustomerVm {
    pub name: Property<String>,
    pub address: forma::binding::Context<AddressVm>,
}
```

```text
TextField {
    key: 'cityInput';
    contextType: 'crate::AddressVm';
    context: state.address;
    value <-> state.city;
}
```

`context` вычисляется в родительском контексте; остальные привязки — в новом.
Альтернативно `value <-> state.address.city` наблюдает вложенный объект без
смены контекста самого контрола. Промежуточные части пути должны быть Context,
конечное поле — Property. Замена `customer.address.set(...)` переключает подписки.

`clear_context()` / `Context::clear()` задаёт пустой контекст: связанные строки
очищаются, ввод и события отключаются. При восстановлении объекта привязки
возобновляются. Смена контекста отменяет незавершённое нажатие и IME preedit,
сбрасывает Undo поля даже при одинаковом тексте двух записей. Фокус сохраняется,
если контрол остаётся доступным. Старые подписки полей снимаются автоматически.

## Подключение к циклу окна

```rust
// Обработчик уведомления только планирует кадр, не рисует синхронно.
form.on_dirty(move || window.request_redraw());

// Каждый входной event проходит через update.
form.update(|runtime| runtime.text_insert("текст"))?;
form.update(|runtime| runtime.pointer(x, y, 1))?;

// runtime() сначала применяет изменения данных и возвращает &Runtime.
let runtime = form.runtime()?;
let pixels = runtime.pixels(360, 180, 1.);
```

`update` применяет накопленные изменения, обрабатывает ввод, записывает новое
значение в модель и вызывает обработчики, затем синхронизирует UI. Обратное
уведомление не создаёт дополнительного шага Undo. `on_dirty` объединяет
уведомления до следующего `sync`; модель не требует постоянного опроса.
Все объекты работают в UI-потоке (`Rc`), фоновые результаты нужно передавать
в него через очередь событий приложения. Замена дерева через `Runtime::load`
внутри update не является поддерживаемой операцией сгенерированной формы.

## Сборка

Генератор использует общий парсер и компилятор компонентов Studio. Он запускается
Node.js из `build.rs`, без новых Rust build-dependencies:

```sh
node scripts/generate-form.mjs \
  --project vector-ui/examples/binding-app \
  --entry ui/CustomerForm.ui \
  --output /tmp/customer_form.rs
```

См. [рабочий build.rs](examples/binding-app/build.rs): он записывает результат
в `OUT_DIR` и объявляет зависимости через `cargo:rerun-if-changed`. Внешний проект
должен также следить за своими assets и JSON-файлом, если передаёт `--state`.
`FORMA_NODE` в примере позволяет указать путь к Node.js.

Неверный синтаксис, неизвестные свойства и необъявленные события дают
диагностику `ui/Form.ui:строка`. Доступ к полям, числовые/логические свойства,
типы контекстов и методы проверяет Rust-компилятор. Генератор записывает
`FILE.map.json`; Studio использует эту карту, чтобы показать исходную строку `.ui`.

## Живая генерация

Генератор сохраняет программу компонентов: наследование, override, `props`,
`state`, чистые выражения, интерполяцию, `match`, списки, вложенный контент, SVG и раскладку.
Rust пересчитывает зависимые свойства при изменении модели. Метрики текста
берутся из Rust; WASM и JavaScript приложению во время работы не нужны.
Генерируются только используемые определения компонентов. Для Text и TextInput
есть встроенные определения; файлы `components/Text.ui` и `components/TextInput.ui`
могут переопределить их для элементов сцены.

- `value <-> state.name`: `Property<String>` у TextField/TextArea; сохраняется Undo.
- `value <-> state.amount`: числовое `Property<T>` у Slider, диапазон `0.0…1.0`
  (например, `f32` или `f64`). В самой разметке задавайте литералы с единицей: `value: 50%;`.
  Числовая привязка `0.5` означает 50%; старый числовой литерал `value: 50;`
  по-прежнему означает 50%.
- `checked <-> state.checked`: `Property<bool>`, переключается при активации.
- `selected <-> state.selected`: `Property<bool>`, устанавливается в true при
  активации; выбор других элементов контролирует модель.
- `property: state.field`: односторонняя привязка свойств, в том числе размеров,
  цветов, многострочного текста, placeholder и параметров вложенного контента.
- `clicked -> state.save()`: вызов метода текущей ViewModel.
- `changed -> events.edited()`: событие после записи пользовательского значения
  в модель. `clicked` также доступен как объявленное событие формы.
- Контейнер с `key` получает типизированный getter `Context<T>`; контрол —
  `Control<T>`. Замена контекста контейнера распространяется на потомков.

```rust
form.slider().bind_range(model.amount.clone());
form.check().bind_checked(model.checked.clone());
form.button().bind_property("width", Property::new(240.0_f64));
form.on_edited(|event| println!("{}", event.context.name.get()));
```

`bind_property` переопределяет одностороннее свойство и пересчитывает зависимые
выражения. Имена в этом низкоуровневом API проверяются при выполнении; свойства
в `.ui` проверяются генератором. Для `value`, `text`, `disabled`, `checked`,
`selected` и числового `range` есть отдельные типизированные методы.

Пересчёт сохраняет фокус, Undo и текущий жест при прежнем контексте. Замена
контекста отменяет старый жест и историю редактирования. При пустом контексте
ввод отключён; текстовые привязки очищаются, другие вычисленные свойства
сохраняют последнее доступное значение до подключения нового контекста.
Если вычисление возвращает ошибку, renderer сохраняет последнюю корректную сцену.

## Выражения и аргументы событий

Зависимости чистых выражений наблюдаются автоматически:

```text
text: '${state.name}: ${state.count + 1}';
width: clamp(state.width - 20, 100, 400);
disabled: state.busy || state.readOnly;
text: state.optionalTitle ?? 'Без названия';
```

`Property<Option<T>>` передаёт `None` как `null`. Доступны арифметика, сравнения,
логические операторы, `?:`, `??`, безопасный доступ `?.`, индексирование и
небольшой набор чистых функций (`min`, `max`, `clamp`, `abs`, `round`, `floor`,
`ceil`, `len`, `String`, `Number`, `Bool`). Произвольный Rust/JavaScript-код
в разметке не исполняется. Ошибка вычисления возвращается из `sync`/`update`.

```text
component Editor {
    contextType: 'crate::EditorVm';
    event saved(id: String, title: String);
    Frame {
        Button {
            clicked -> events.saved(state.id, state.title);
        }
    }
}
```

Генератор создаёт `EditorSavedEvent` с полями `id: String`, `title: String`,
`context: Rc<EditorVm>` и `control_index: usize`. `on_saved` принимает этот тип.
Поддержаны `String`, `Bool`, `Number` (`f64`), `Int` (`i64`) и их nullable-варианты
с `?`; число и типы аргументов проверяются до вызова обработчика.
`changed` вычисляет аргументы после записи пользовательского значения в модель.
Обработчик получает текущий контекст и актуальный индекс, включая перестановки
элементов. Имена аргументов `context` и `control_index` зарезервированы.

## Коллекции и устойчивая идентичность

```text
for task in state.tasks key task.id {
    TextField {
        key: 'editor';
        value <-> task.title;
        changed -> events.edited(task.id, task.title);
    }
} empty {
    Button { text: 'Нет задач'; disabled: true; }
}
```

`tasks` — `Property<Vec<Task>>`; `Task` содержит обычные поля и реализует
`Clone + PartialEq`. Генератор сам проецирует используемые поля, отдельный
`ModelValue` для такой структуры не нужен. Обновляйте коллекцию через `set`:

```rust
let mut tasks = model.tasks.get();
tasks.reverse();
model.tasks.set(tasks);
form.sync()?;
```

Строковые/числовые ключи должны быть уникальны в пределах одного `for` и
оставаться стабильными для одной записи. При добавлении, удалении и перестановке
фокус, текст и Undo следуют за ключом. Удалённый контрол перестаёт получать
события. Идентичные локальные key внутри шаблона получают область текущей записи;
обращение к экземпляру в событии всегда использует его актуальный индекс.

Поддержаны вложенные коллекции (`for child in task.children key child.id`),
простые массивы строк и чисел, а также `if … { … } else { … }`.
Вложенные циклы используют разные имена переменных. Двусторонняя запись
`value`, `checked`, `selected` в поле элемента обновляет соответствующую
коллекцию; удалённая или заменённая во время ввода коллекция не получает
устаревшую запись. Элементы коллекции используют контекст окружающей формы;
нужную запись передавайте через типизированные аргументы события.

Именованный getter контрола в повторителе возвращает handle шаблона, а `index()` —
первый видимый экземпляр (или `usize::MAX`, если экземпляров нет). Для выбора
конкретной записи используйте key либо `event.control_index`.

Параметры корневой формы можно передать через
`FormName::with_properties(model, forma::form_document::props(...))`;
`FormName::new(model)` использует значения по умолчанию. Обязательные параметры,
типы, enum, групповой `match` и `forward` проверяются и исполняются модулем
компонентов в Rust.

Полный запускаемый пример: [examples/language-app](examples/language-app).
Он проверяет редактирование, перестановку с сохранением фокуса, удаление,
условные ветки, типизированные события и Row/Grid без оконного сервера.

## Проект и Studio

Без `--entry` CLI генерирует все формы с `contextType` из `ui/` в один Rust-файл.
`--state file.json` задаёт статические данные сборки, например тему.

В Studio кнопка «Приложение» для формы с `contextType` генерирует формы проекта
и запускает пользовательский `src/main.rs`. Проект должен содержать Cargo.toml
с `forma = { path = "…" }` в dependencies. Runtime подключается из текущего
репозитория. В Rust подключите результат:

```rust
include!("forma_generated.rs");
```

`src/forma_generated.rs` создаётся во временном проекте и не изменяет исходники
Studio. `main` создаёт ViewModel, форму и оконный хост; рабочий пример хоста
находится в `examples/binding-app/src/window.rs`. «Стоп» завершает этот процесс.
Встраиваемый preview остаётся редактором снимков; живой Rust выполняется через
запуск приложения.

Генерация поддерживает корневой Frame, Row, Column, Grid или Stack,
вложенный Scroll, условные ветки и динамические коллекции. Бизнес-валидация и произвольные
вызовы функций в выражениях остаются задачей модели.

Проверки `node --test test/form-codegen.test.js` компилируют и исполняют
сгенерированный каталог и живые формы, проверяют модель, события, геометрию,
цвета, многострочный ввод, вложенные коллекции, сохранение фокуса при перестановке,
типизированные аргументы событий и отказы сборки для неверных полей/типов.

## Подсказки редактора

Studio предлагает свойства и компоненты во время ввода, включая наследование,
`state.`, `props.`, `events.`, вложенные контексты и вызовы команд ViewModel.
`Ctrl+Space` открывает список вручную, `Tab` или `Enter` принимает подсказку,
`Escape` закрывает. У поля отображается тип `Property<T>` или `Context<T>`.

Поля и методы берутся из Rust-файлов проекта без запуска кода. Индекс поддерживает
обычные объявления struct и impl, в том числе файлы модулей. Макросы, сложные
обобщённые типы и разрешение импортов требуют полноценного Rust language server;
текущие Rust-подсказки включают типы проекта и конструкторы Forma.
