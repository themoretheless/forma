# Архитектурные этапы — 6 сентября 2026

Это журнал выполненных шагов, а не заявление о завершении всей миграции.
Изменения существующей оптимизации GPU описаны отдельно в
[OPTIMIZATION_STEPS.md](OPTIMIZATION_STEPS.md).

## 1. Исправления корректности — выполнено

- Инспектор заменяет диапазон значения из парсера, а не совпадение regex.
  Строки с `;`, кавычками и переносами не повреждаются. Изменение проходит
  через транзакцию CodeMirror с undo/redo. Исправлено повторное декодирование `\\n`.
- Disabled Border сразу получает disabled-цвет, ещё до первого события.
- Space/Enter обрабатывает общий Rust `key_event`: нажатие, отпускание,
  игнорирование повторов и отмена при потере фокуса. Native и web используют его.
- Размер текста по контенту берётся из метрик того же встроенного Rust-шрифта,
  которым рисуется текст. Эвристика `число символов × 0.56` удалена.
  Это ещё не shaping, перенос строк или font fallback.

Проверка: 75 JS-тестов, 68 Rust-тестов; один аппаратный тест пропущен.
54 GPU golden-изображения совпали побайтно.

Бенч после этапа: `.forma/perf/architecture-1-correctness-2026-09-06/`.
33 процесса: 3 повтора × 11 сценариев, по 120 кадров после прогрева.
Аллокации GPU animation — 43.25/кадр, resize — 54.67/кадр, без изменений.
Состав и ёмкости GPU-буферов не изменились. Времена шумные, ускорение не заявляется.

## 2а. Дерево и происхождение элементов — выполнено

`compileComponents` возвращает дополнительно два неизменяемых snapshot:

- `instanceTree`: исходная иерархия экземпляров, до замены типа на Button;
- `templateTree`: раскрытая визуальная иерархия, до удаления key и flatten.

Каждый узел содержит локальный числовой ID, parent/children, отдельный key,
свойства, события и source `{file, from, to}`. Диапазоны — UTF-16 для редактора,
не байтовые смещения Rust. `propertySources` указывает место определения
выражения свойства, не происхождение его вычисленного значения.
При `override from` файл свойства сохраняется; локальный override имеет приоритет.
Условно выбранный элемент сохраняет свой исходный файл.

ID действуют только внутри одного snapshot: стабильная идентичность между
перекомпиляциями и scoped reconciliation ещё не реализованы. Key не используется
как глобальный ID. Синтаксический запрет дубликатов key внутри компонента сохранён.
Текущее дерево дизайнера ещё не переведено на новые snapshot.

Бенч после этапа: `.forma/perf/architecture-2-source-tree-2026-09-06/`.
Полная серия renderer повторена. Сгенерированные source/template и Rust binary
не менялись на этом этапе; изменения времени нельзя приписывать дереву.
Аллокации и размеры GPU-буферов прежние. Например, 4K animation: 179.20 → 181.72
offscreen кадров/с, resize: 90.33 → 93.76; текст 1080p: 278.39 → 206.71.
Разнонаправленный шум приведён без отбора только удачных результатов.

Добавлен отдельный `scripts/compiler-bench.mjs`: 7 серий по 500 компиляций,
100 прогревочных вызовов. На небольшой ImageButton-сцене медиана выросла
с 0.172 до 0.279 мс (+62%, +0.107 мс). Это цена построения metadata snapshot,
не оптимизация компилятора. SHA-256 входов и сгенерированного кода совпадают.
Замер одной пары процессов предварительный; не прогноз для крупных документов.
Heap delta включает мусор GC и не является числом аллокаций/retained memory.

## 2б. Runtime-дерево и независимые контролы — выполнено

Общий `Runtime` используется Studio/WASM, native и benchmark executable.
Он хранит Frame → [Scroll →] Control, отдельные состояния, фокус, захват указателя
и адрес последнего события. Проверяемый результат: две кнопки в одном Frame
с независимыми hover/pressed/focus/click. Tab/Shift+Tab меняют фокус, Space/Enter
активируют только текущий контрол. Disabled пропускаются при навигации; нажатие
на одном контроле с отпусканием на другом не вызывает click. Верхний disabled
контрол не пропускает клик к перекрытому соседу. Clip и Scroll охватывают группу.

`compileComponents` раскрывает каждый экземпляр, включая разные наследники
и их визуальное содержимое. Для нескольких шаблонов используется временный
транспорт `FORMA-TEMPLATES-1` с длинами UTF-8; это ещё не типизированный IR.
Одношаблонный формат и прежний `Button` API сохранены для совместимости.
`instanceTree` остаётся исходным деревом, `templateTree` содержит корень каждого
раскрытого шаблона. Выбор мышью в дизайнере и журнал событий различают контролы
по индексу в текущем snapshot; MCP `vector_status` возвращает массив `controls`.

Native renderer получает `RenderScene` (геометрию и paint slots), без знания
о Button или обработчиках. Каждый контрол занимает два независимых цветовых
слота. Native wgpu и WebGPU используют один shader и отдельный storage buffer
красок; анимация не пересоздаёт геометрию. CPU fallback сохраняет существующий
поконтрольный растеризатор; при нескольких контролах он композитит их слои.
Это пока не оптимизация памяти/resize многоконтрольного CPU fallback.

Проверки:

- 75 обычных Rust-тестов, 80 JS-тестов, включая реальный WASM с двумя разными
  шаблонами, некорректной повторной загрузкой и маршрутизацией событий.
- Два аппаратных теста Metal: переиспользование буферов и независимость пикселей
  контролов при DPI 1/1.25/2. При анимации первого вся область второго совпадает
  побайтно, geometry uploads не растут.
- Все 54 старых GPU golden-изображения совпали побайтно через новый Runtime.
- Универсальная CPU/GPU проверка большой TwoButtons-сцены при DPI 1.25 превышает
  прежний порог числа отличающихся каналов: 4014 при пороге 2500, средняя ошибка
  0.0847/255. Расхождения преимущественно на тонких границах (разные методы AA);
  допуск не ослаблен, побайтное равенство CPU/GPU не заявляется.
- Release native, WASM и production Studio собраны. В браузере проверены
  WebGPU, клики обеих кнопок, Enter/Space, Shift+Tab и выбор второй в дизайне.
  Native-окно запущено на Metal; его журнал подтвердил отдельные
  `first.clicked` и `second.clicked`. Оконный FPS этим этапом не измерялся.

Бенч после этапа: `.forma/perf/architecture-2b-runtime-2026-09-06/`.
33 процесса, прежние fixtures и SHA-256, 3 × 120 кадров после 20 прогревочных.
GPU animation: 43.25 → 44.50 alloc+realloc/кадр; resize: 54.67 → 55.67.
Цветовой buffer одноконтрольной сцены добавляет 32 байта native GPU capacity.
Времена разнонаправленные: 4K animation 181.72 → 320.95 offscreen кадров/с,
текст 206.71 → 159.37, nested clip 149.91 → 125.36; ускорение и отсутствие
регрессий времени не заявляются на не изолированной от нагрузки машине.
Отдельно TwoButtons: 3 процесса × 120 кадров, 800×600 DPI 2, медиана
636 offscreen кадров/с, completed p95 1.602 ms, 45.875 alloc+realloc/кадр,
36 976 байт owned GPU buffers. Это не FPS экрана и не вся VRAM.

Пример: `examples/TwoButtons.ui`; браузерный стенд при запущенном Vite:
`/vector-ui/examples/runtime.html`.

Ограничения этапа: один корневой Frame, вертикальная раскладка с padding/gap,
до 256 контролов (или один Scroll с ними); шаблоны пока имеют корневой Rectangle.
Произвольные вложенные интерактивные контейнеры и другие виды input-контролов
не добавлены. ID локальны snapshot; при редактировании многоконтрольная сцена
сбрасывает взаимодействие. Стабильные ID/reconciliation — следующий этап.
Свойства, bindings, новые типы/стили и вызов прикладного кода намеренно отложены
до отдельного обсуждения с пользователем. События по-прежнему попадают в журнал.

## Оставшаяся работа — НЕ выполнена

1. **Стабильные идентификаторы и дизайнер.** Перевести выбор/инспектор/MCP на
   snapshot и origin; reconciliation после редактирования, включая наследование.
2. **Общий compiler/layout Rust → native/WASM.** Типизированный IR вместо
   промежуточной сериализации `.ui` и повторного парсинга. Lezer остаётся редактору.
3. **Реестр свойств и bindings — отложено до обсуждения.** Типы, стили,
   зависимости, инвалидация layout/paint, связь событий с кодом приложения.
4. **Общий текстовый и input-слой.** Shaping, переносы, fallback, IME, accessibility.

После каждого следующего завершённого шага нужна своя серия с теми же fixture
hashes, плюс тесты нового поведения. Offscreen throughput не является FPS окна;
owned GPU bytes — не измерение всей резидентной VRAM.
