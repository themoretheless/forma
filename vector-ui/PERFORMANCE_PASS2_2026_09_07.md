Baseline — `e86a17144e471566a5958276d6031b0215962943`, уже содержащий
[первый проход](PERFORMANCE_2026_09_07.md). Apple M5, 24 GiB, release.
Исходники baseline получены через `git archive`. Одинаковые новые измерители
собраны на обеих версиях с default features в **раздельных Cargo target dirs**.
Бинарники, SHA-256, порядок процессов и сырые результаты сохранены локально

## CPU-композиция нескольких контролов

Четыре пары AB/BA, ниже медианы четырёх процессов каждой версии. Физический
буфер 640×360, DPI 1,25. Cold — первая растеризация уже созданного Runtime;
warm — 30 неизменных кадров; animation — 48 кадров с чередованием hover/leave
и tick. XRGB host buffer выделен заранее, вывод на экран не измеряется.

| Сценарий | До, мс/кадр | После, мс/кадр |
|---|---:|---:|
| 1 контрол, cold | 1,694 | 1,701 |
| 1 контрол, warm | 0,0101 | 0,0099 |
| 1 контрол, animation | 0,518 | 0,522 |
| 8 контролов, cold | 15,30 | 2,89 |
| 8 контролов, warm | 3,092 | 0,00995 |
| 8 контролов, animation | 4,377 | 0,669 |
| 32 контрола, cold | 57,14 | 6,57 |
| 32 контрола, warm | 8,580 | 0,0101 |
| 32 контрола, animation | 11,172 | 0,877 |

Удерживаемые Rust-байты включают Runtime и его кэши, исключают заранее
созданный host buffer. Трафик allocator — суммарно запрошенные байты,
а не одновременно занятая память. Счётчик учитывает Rust GlobalAlloc.

| 32 контрола | До | После |
|---|---:|---:|
| Удерживаемая память сцены | 45 072 619 байт | 3 651 915 байт |
| Alloc + realloc / warm или animated кадр | 33 | 0 |
| Трафик allocator / warm или animated кадр | 30 412 800 байт | 0 |
| Alloc + realloc / cold кадр | 1 057 | 1 187 |
| Трафик allocator / cold кадр | 105 647 968 байт | 41 217 216 байт |

Кэш каждого дочернего контрола хранит coverage и RGBA только для непустых
участков строк, сохраняя исходные физические координаты сэмплов. Общие frame,
scroll clip, RGBA и XRGB переиспользуются на уровне Runtime. Композиция читает
заимствованные участки дочерних кэшей без клонирования full-canvas буферов.
Неизменный root frame возвращается из кэша: строка warm измеряет его копирование,
а не повторную растеризацию всей сцены. Геометрия инвалидируется при resize,
DPI и scroll; paint — по visual revision и фону. Восстановление Reveal при
reconciliation теперь тоже обновляет visual revision.

Есть ограничения: первый build всё ещё использует временный full-canvas scratch;
количество cold-аллокаций выросло примерно на 12%, хотя их объём уменьшился.
Общий retained root cache занимает около 9 байт на пиксель. На сцене из двух
контролов, полностью перекрывающих viewport, память может вырасти; выигрыш
для любой геометрии не заявляется. Одна кнопка сохраняет отдельный dense путь
и практически прежнюю скорость; её retained overhead увеличился на 88 байт.

## Текстовая геометрия

Те же четыре пары, по 100 операций. `button_build` строит DisplayList для
64 текстовых блоков, минуя постоянный кэш. `runtime_scroll` включает
инвалидирование и перестройку объединённого списка 64 контролов.

| Сценарий | До | После |
|---|---:|---:|
| DisplayList, 64 текстовых блока | 0,829 мс | 0,770 мс |
| Alloc + realloc / такой build | 2 395 | 33 |
| Трафик allocator / такой build | 3 824 752 байт | 2 526 256 байт |
| Scroll, 64 контрола | 0,896 мс | 0,846 мс |
| Alloc + realloc / такой scroll | 3 415 | 1 431 |
| Трафик allocator / такой scroll | 6 185 488 байт | 5 141 008 байт |

Контуры направляются сразу в DisplayList; промежуточные Vec каждого glyph и
Vec<Vec> удалены. Один transient scratch переиспользуется в пределах build
и освобождается после него. Порядок f32-операций и разбиение кривых сохранены.
Глобальный glyph cache не добавлялся; scroll по-прежнему перестраивает геометрию.
Прогретый snapshot и до изменения не аллоцировал, его ускорение не заявляется.

## Studio

Node v22.23.2 с `--expose-gc`, две пары AB/BA, внутри процесса пять пакетов
после прогрева. Хеши fixtures и сгенерированных source/template совпали.

| Компиляция ImageButton в сессии | До, мс | После, мс |
|---|---:|---:|
| 1 контрол | 0,235 | 0,201 |
| 64 контрола | 10,22 | 3,31 |
| 256 контролов | 41,72 | 14,33 |

Lowering больше не мутирует исходное дерево, поэтому две полные глубокие копии
убраны. Immutable element tree отделяется одним structuredClone после проекции
вместо пяти вызовов на узел. Метрики повторяющегося текста и результат lowering
SVG переиспользуются внутри одной компиляции. SVG-кэш ограничен 1 000 000
UTF-16 единиц результата; это ограничение объёма строк, не точный heap size.
Callbacks сохраняют исходный receiver и методы прототипа.

| Обработка исходников Studio | До, мс | После, мс |
|---|---:|---:|
| Свёрнутое дерево, 10 000 дочерних узлов | 0,0964 | 0,000280 |
| Развёрнутое дерево, те же узлы | 0,306 | 0,181 |
| Folding: 1 024 вложенных блока и строка 64 KiB | 1,289 | 0,250 |
| Folding: 4 096 плоских блоков | 0,560 | 0,420 |

Без поиска дерево обходит только видимые ветви. Выбор и клавиатурный фокус
обновляют существующие DOM-строки; неизменный документ повторно не парсится.
Folding определяет наличие перевода строки за один проход без slice для
каждой пары скобок. Canvas tools получают кешируемый immutable geometry snapshot
без labels, actions и текстовых значений каждого контрола. Закрытый inspector
и скрытые направляющие пропускают ненужное построение содержимого.

Эти измерители не оценивают JS allocation counts, GC pauses, RAM вкладки или
browser layout/paint. Время синтетического дерева не является временем всей UI
операции. GPU shaders и качество AA не менялись; новые FPS GPU/окна не измерялись.

## Проверки и воспроизведение

- 124 обычных Rust-теста и отдельно 3 аппаратных теста Metal прошли.
  Native release executable, свежий WASM и production Studio собраны.
- 171 JS-тест прошёл без пропусков. Выходы компилятора также сопоставлены
  через deepEqual на 184 вариантах fixtures галереи.
- Побайтовые reference-тесты CPU покрывают overflow текста/фигур, clipping,
  scroll, resize, fractional DPI, пустые сцены и Reveal-only reconciliation.
  Отдельная allocation-регрессия требует ноль вызовов heap на прогретых
  static/animated native кадрах нескольких контролов при DPI 1 / 1,25 / 2.
- Геометрия контуров совпадает с прежним алгоритмом на 225 сочетаниях текста,
  размера, DPI и дробного origin. Во всех парах benchmark совпали geometry/pixel
  hashes, включая текстовые CPU-пиксели при DPI 1 / 1,25 / 2.
- Browser smoke: выделение, collapse/expand дерева и inspector работают;
  все 22 секции галереи используют WebGPU. Ошибок приложения нет.
  Пользовательские файлы/настройки сохранены, проверочные вкладки закрыты.

```sh
cargo run --offline --release --manifest-path vector-ui/Cargo.toml --example multicontrol_perf
cargo run --offline --release --manifest-path vector-ui/Cargo.toml --example text_perf
node --expose-gc scripts/compiler-session-bench.mjs .forma/perf/compiler-session
node --expose-gc scripts/studio-tools-bench.mjs .forma/perf/studio-tools
```

Для A/B нужно скопировать эти же Rust examples в архив baseline, собрать версии
с разными `--target-dir`, сохранить executable и запускать последовательно
AB/BA без сборок в измеряемом интервале. JS-измерители принимают третий аргумент:
путь к `src/components.js` для compiler и корню исходников для studio-tools.
Фоновая нагрузка и DVFS машины не изолированы.

Первая попытка с общим Cargo target dir дала идентичные A/B executable и
исключена; она хранится в `invalid-shared-target/`. Следующая серия обнаружила
20% замедление dense repaint одной кнопки; после специализации этого цикла
измерение повторено. Промежуточные результаты находятся в `before-dense-fix/`;
таблицы выше относятся только к окончательной серии с различающимися хешами
бинарников и `hashesMatch: true`.
