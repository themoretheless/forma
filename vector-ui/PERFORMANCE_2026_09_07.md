# Оптимизация библиотеки и Studio — 7 сентября 2026

Сравнение с рабочим деревом перед этой оптимизацией, включая уже существовавшие
незакоммиченные изменения. Это новый baseline, а не исходные числа от 6 сентября.
Снимок исходников, executable до/после, хеши и результаты сохранены локально в
`.forma/perf/optimization-2026-09-07/`. Измерения: release, Apple M5, 24 GiB.

## Библиотека: CPU и аллокации

Четыре последовательные пары AB/BA; ниже медианы процессов. Загрузка измеряется
без уничтожения созданного Runtime. Аллокации учитывают Rust GlobalAlloc;
запрошенные байты — трафик, не одновременно занятая RAM.

| Сценарий | До | После |
|---|---:|---:|
| Загрузка 64 контролов | 2,57 мс | 0,332 мс |
| Загрузка 256 контролов | 36,8 мс | 1,30 мс |
| Alloc + realloc на загрузку 256 контролов | 951 620 | 30 277 |
| Трафик allocator на загрузку 256 контролов | 61 006 588 байт | 1 890 044 байт |
| Pointer, 256 контролов | 18,1 мкс | 6,48 мкс |
| Alloc + realloc на pointer, 256 контролов | 510,5 | 0 |
| Idle tick, 256 TextInput | 526 мкс | 6,35 мкс |
| Alloc + realloc на idle tick, 256 TextInput | 768 | 0 |
| Idle tick, 256 RangeInput | 21,9 мкс | 5,39 мкс |
| Alloc + realloc на idle tick, 256 RangeInput | 512 | 0 |

Из загрузки удалено квадратичное клонирование всех соседей для каждого контрола.
Внутренние hit-test/viewport используют фиксированные массивы. Индекс ключей
переиспользуется при восстановлении редакторов. Неизменные TextInput/RangeInput
не пересобирают содержимое на каждом tick; метрики шрифта используют один parsed
Face, а поиск позиции каретки проходит строку за линейное время.

Обычный idle tick без редакторов и раньше не аллоцировал: для 256 контролов
5,02 → 5,08 мкс. Ускорения этого случая не заявляем. Анимирующаяся каретка,
изменённый текст и scroll по-прежнему могут перестраивать геометрию.

Запуск нового измерителя:

```sh
cargo run --offline --release --manifest-path vector-ui/Cargo.toml --example runtime_perf
```

## CPU renderer и память

Четыре пары, 20 кадров прогрева и 120 измеряемых кадров, DPI 2. CPU пишет в
заранее выделенный XRGB host buffer; загрузка на экран и present не измеряются.

| Сценарий | До | После |
|---|---:|---:|
| Кнопка 4K, анимация: offscreen кадров/с | 357 | 403 |
| Та же сцена: completed p95 | 3,00 мс | 2,76 мс |
| Alloc + realloc за 120 кадров | 179 | 0 |
| Трафик allocator за 120 кадров | 152 320 960 байт | 0 |
| Живые Rust-байты после серии | 38 014 219 | 36 459 758 |
| Текст + nested clip, 1080p forced: живые Rust-байты | 40 714 634 | 31 815 497 |

CPU cache упаковывает frame/viewport в один байт и сохраняет RGBA содержимого
только для непустых участков строк. XRGB сохраняет capacity при repaint;
временные слои переиспользуются между соседними clip, а композитинг ограничен
консервативной областью clip с запасом для AA. Polygon rasterizer переиспользует
массивы coverage/intersections между строками. Порядок наложения и AA сохранены.

Nested forced измеряет повторное использование готового кадра. Его throughput
2384 → 2453 не является замером полной растеризации текста на каждом кадре.
В этом случае build + warmup составил 111 → 118 мс: ускорения холодного пути
на всех сценах не заявляем. RSS и живые Rust-байты различаются: RSS в этой сцене
143 376 384 → 139 460 608 байт, он включает allocator и другие ресурсы процесса.

## Native GPU

48 последовательных процессов: 4 пары AB/BA на каждую из 6 сцен, по 240 кадров
после 20 кадров прогрева. Полный отчёт с диапазонами и хешами:
`.forma/perf/optimization-2026-09-07/gpu-paired/REPORT.md`.

| Сценарий | До | После |
|---|---:|---:|
| Кнопка, анимация: alloc + realloc / кадр | 44,5 | 39,97 |
| Кнопка, анимация: загружено байт / 240 кадров | 19 200 | 7 648 |
| Resize около 4K: alloc + realloc / кадр | 55,67 | 51,67 |
| Nested forced: alloc + realloc / кадр | 44 | 32 |
| Nested forced: загружено байт / 240 кадров | 19 200 | 0 |
| Nested forced: CPU submit mean | 0,226 мс | 0,114 мс |

Для nested forced снижение CPU submit воспроизвелось во всех четырёх парах
(−57…−38%). В GPU-сериях оставшиеся аллокации включают wgpu/driver interface;
это не противоречит нулевым аллокациям подготовки параметров самой Forma.
Новые retained scratch/copies параметров занимают 160 байт для этих сцен и
явно учтены в `cpu_paint_scratch_bytes`. Geometry uploads при анимации — 0,
новые наши GPU buffers в измеряемых сериях — 0, как и до изменения.

Устойчивого общего прироста GPU FPS не установлено: медианы попарных изменений
throughput по сценам −2,2…+3,9%, диапазоны перекрываются. Shader не менялся;
различия GPU timestamps не приписываем этим CPU/cache оптимизациям. Измерения
offscreen не являются частотой вывода native окна на экран.

## Studio

Две пары AB/BA, внутри каждого процесса пять пакетов после прогрева, Node
v22.23.2 с `--expose-gc`. Сцены содержат ImageButton с наследованием и SVG.
Все хеши сгенерированных source/template до и после совпали.

| Компиляция в сессии редактора | До | После |
|---|---:|---:|
| 1 контрол | 0,586 мс | 0,462 мс |
| 64 контрола | 26,6 мс | 20,2 мс |
| 256 контролов | 105 мс | 81,7 мс |

Шаблон разделяется между экземплярами внутри компиляции; копия нужна только
наследнику для override. Session compiler сохраняет последние parsed документы
с проверкой содержимого: до 128 записей и 1 000 000 UTF-16 единиц исходников.
Это ограничение входа кеша, не точный размер AST в памяти. State, presets,
transformScene и callbacks вычисляются заново; linked/output деревья не кешируются.

Неизменный preview больше не растеризуется при выборе элемента или resize с
теми же физическими размерами. ImageData использует представление готовых RGBA
байтов без второй копии; CPU canvas освобождается при переходе на GPU и destroy.
Native/WebGPU переиспользуют params/paints и не загружают неизменные параметры.
После частично неудачного upload все ключи инвалидируются для корректного retry.
CodeMirror кеширует строку документа до правки; позиция курсора берётся из
дерева строк без пересборки всего текста и скрытой линейки номеров.

```sh
node --expose-gc scripts/compiler-session-bench.mjs .forma/perf/compiler-session
```

Этот benchmark не измеряет число JS-аллокаций, GC pauses, browser FPS или RAM
вкладки. Значения времени зависят от фоновой нагрузки; парные запуски уменьшают
влияние порядка, но не изолируют машину.

## Проверки

- Итоговая Rust-проверка: 116 обычных тестов и отдельно все 3 аппаратных теста
  Metal прошли. Native release executable собран. Проверено отсутствие повторных
  upload и независимость пикселей контролов при DPI 1 / 1,25 / 2.
- Новые allocation-регрессии требуют ровно 0 alloc/realloc в прогретых
  pointer/tick, сериализации GPU параметров и native CPU repaint.
- CPU reference-пиксели проверяют sparse content, вложенные/соседние clip и
  fractional AA; tests также проверяют кеш редактора и Unicode caret hit-test.
- JS-регрессии проверяют инвалидирование source cache, независимость экземпляров,
  ошибки/retry GPU, повторный render, buffer byteOffset и освобождение canvas.
- Свежий WASM собран, 148 JS-тестов прошли без пропусков; production Studio собрана.
- Browser smoke: Studio без ошибок, позиция курсора корректна; все 22 preview
  каталога работают через WebGPU. Исходники виртуального проекта и настройки
  пользователя не менялись; созданные вкладки закрыты.

Первая попытка nested CPU animation была отклонена самим benchmark: fixture
не содержит перехода. В итоговой серии используется forced; неполная попытка
сохранена отдельно. Metal недоступен внутри файловой песочницы; аппаратные
проверки выполняются с доступом к GPU вне неё.
