# Кэши и ключи Forma

Проверка 7 сентября 2026, после второго прохода оптимизации. Полный хеш дерева
на каждом кадре не заменяет версионирование: его вычисление само требует обхода
дерева. Горячий путь использует identity и версии; хеши нужны для независимых
артефактов и проверки воспроизводимости.

## Изменения этого прохода

- Добавлен `Runtime.layout_revision()`: scroll и загрузка исходников меняют
  версию, а hover, анимация цвета и изменение текстового содержимого — нет.
  Размеры контролов задаёт загруженный layout, текст не меняет их автоматически.
  `layoutSnapshot()` больше не создаёт новые bounds при каждом изменении paint.
- WebGPU использует scalar layout version вместо `scroll_offset()` с новым
  WASM/JS массивом на каждом кадре. Для старых адаптеров сохраняется точное
  сравнение scroll. При отсутствии geometry version используется visual version;
  без обеих версий геометрия загружается повторно, чтобы не оставить старый кадр.
- `Runtime.load()` / `load_component()` теперь изменяют все три версии.
  Раньше содержимое того же WASM-объекта заменялось с обнулением счётчиков:
  ключ `(model identity, revision)` мог остаться прежним.
- Native и WebGPU вызывают `release_cpu_cache()` после успешной отправки кадра.
  Удаляются CPU coverage, RGBA и XRGB, включая дочерние растры. DisplayList и
  геометрия GPU остаются. Fallback лениво восстанавливает CPU-кэш. Для нескольких
  контролов наличие root raster позволяет пропускать обход уже освобождённых
  листьев на следующих GPU-кадрах. Внешние реализации `RenderScene` имеют
  совместимый default hook без действия.

## Какие ключи подходят существующим слоям

| Слой | Ключ / проверка | Время жизни |
|---|---|---|
| Parsed source компилятора | Тип документа, путь, точное содержимое строки | Общий LRU Studio: 8 MiB расчётного веса, максимум 256 записей |
| Linked components | Имя и точные исходники транзитивных зависимостей | Тот же общий LRU |
| Документы Control Tree | Путь и точное содержимое | Тот же общий LRU; активное дерево — живое UI-состояние |
| Метрики текста | Текст и размер при одном callback | Одна компиляция |
| Lowered SVG | Точное содержимое SVG, bounds, цвет | Одна компиляция, до 1 000 000 UTF-16 единиц результата |
| Native geometry | Удерживаемый immutable Arc identity, DPI, background; scroll внутри ключа модели | Один текущий snapshot |
| WebGPU geometry | Model identity, geometry/layout versions, scale | Один текущий набор GPU-буферов |
| GPU tiles | Ключ геометрии и размеры сетки тайлов | Один текущий набор |
| Paint | Visual version; native также сравнивает подготовленные параметры | Текущий кадр |
| Canvas tools bounds | Model identity и layout version | Один immutable snapshot |
| CPU raster | Размеры, DPI, scroll, paint revision / параметры | Текущий размер; освобождается при переходе на GPU |

SVG-лимит в UTF-16 единицах ограничивает строки, а не точное число байтов heap.
Общий LRU учитывает оценку вложенных объектов, массивов, строк и dependency maps,
включая linked AST. Это расчётный вес, а не точное измерение heap конкретного VM.
Активные документы/DOM, текущие результаты компиляции и GPU-ресурсы не входят
в этот бюджет. Переполнение вытесняет наименее недавно использованные записи;
слишком большая запись возвращается вызывающему коду без сохранения в кэш.
Буферы с retained capacity могут сохранять максимальный достигнутый размер.
Map со строковыми ключами проверяет равенство ключа; отдельный короткий хеш
не должен становиться единственным доказательством равенства исходников.
Версии — локальные u32-счётчики с wrapping, не постоянные идентификаторы файлов.

## Где хеши имеют смысл

SHA-256 подходит для сохранённых исходников, fixtures, бинарников и дискового
кэша между процессами. Такой ключ должен включать версию компилятора, опции,
исходники зависимостей, SVG и используемый шрифт. Вычислять его нужно при
изменении входа, а не при paint. Быстрый некриптографический хеш можно применять
как предварительный фильтр, сохраняя проверку исходного ключа при совпадении.

Session compiler теперь сохраняет чистые связанные определения компонентов.
Для каждого результата хранится транзитивный набор исходников: собственный
компонент, цепочка базовых компонентов и файлы `override from`. Проверка ленивая:
при запросе определения сравниваются только его зависимости. Чужой файл не
сбрасывает кэш; изменённый или удалённый dependency запрещает reuse. Глубина
наследования сохраняется вместе с записью, поэтому hit не обходит лимит 32.

Сохранённое определение отделяется копией; на hit выдаётся отдельная копия,
чтобы caller mutation визуального snapshot не отравляла следующие компиляции.
Композиция вложенных компонентов, SVG, state, font metrics, transformScene и
instanceProps выполняются заново. Полный output cache и инкрементальное
перестроение раскладки не добавлялись: для них потребуется больше зависимостей,
чем один хеш entry-файла.

Для glyph cache сначала нужно отделить локальную геометрию от transform с
оговорённой точностью. Перенос готовых контуров сейчас способен изменить
порядок f32-округления и fractional AA. Ради такого кэша качество не менялось.

Неактивные source-деревья Control Tree больше не накапливаются без лимита.
Остаётся отдельная задача native renderer: CPU/GPU capacity ограничена размерами
ресурсов, но не единым бюджетом сцены. JS-бюджет не ограничивает Rust/VRAM.

## Проверка освобождения памяти

`cargo run --offline --release --manifest-path vector-ui/Cargo.toml --example cache_perf`
строит geometry и CPU raster, вызывает тот же release hook, затем проверяет
неизменность geometry identity и точное воспроизведение CPU-пикселей.
Физический буфер 640×360, DPI 1,25; это измерение Rust GlobalAlloc, не RSS/VRAM
и не производительности GPU.

| Контролов | Освобождено Rust-байт |
|---|---:|
| 1 | 2 307 104 |
| 8 | 2 281 672 |
| 32 | 2 905 888 |

Последующие 100 release-вызовов не вызывают alloc/realloc/dealloc. Сцена одной
кнопки использует dense raster, поэтому её размер не обязан быть меньше
packed multi-control cache. CPU fallback после device loss потребует холодного
восстановления кэша; это сознательная плата за освобождение памяти на GPU-пути.

Прошли 126 обычных Rust-тестов, 3 аппаратных Metal-теста и 176 JS-тестов.
Собраны native release, свежий WASM и production Studio. Тесты покрывают
same-object reload, paint-only layout reuse, legacy adapters, частичный upload
failure, освобождение после submit и точность fallback для 0 / 1 / 2 контролов.
Логи и измерения: `.forma/perf/cache-review-2026-09-07/`.

## Общий бюджет и зависимости: дополнительная проверка

183 JS-теста и production-сборка прошли. Новые тесты проверяют LRU между
пространствами имён, переполнение расчётного byte budget, oversized записи,
нулевой бюджет, циклы, глубину наследования, транзитивные override, независимые
правки файлов, вложенную композицию и изменённые SVG. Результаты с кэшем и без
него сравниваются через deepEqual. Rust в этом этапе не менялся.

`createComponentCompiler({cache})` принимает общий `createCacheBudget()`;
Studio передаёт тот же экземпляр Control Tree. `compile.cacheStats()` показывает
расчётные байты, число записей, вытеснения и linked hits/misses. Это диагностический
API; данные компиляции от этих счётчиков не зависят.

Измерители: `scripts/compiler-session-bench.mjs` и
`scripts/compiler-dependencies-bench.mjs`. Исходники до изменения, парные серии
и логи сохранены в `.forma/perf/dependency-cache-2026-09-07/`.

Итоговая серия: четыре пары AB/BA, Node v22.23.2 с `--expose-gc`, пять пакетов
после прогрева в каждом процессе; ниже медианы процессов. Хеши fixtures и
результатов до/после совпали. Это CPU-время компиляции, не FPS Studio.

| Сценарий | До, мс | После, мс |
|---|---:|---:|
| Цепочка из 24 компонентов, повторная компиляция | 0,602 | 0,0782 |
| Та же цепочка, правка override последнего наследника | 0,605 | 0,161 |
| ImageButton, 1 контрол, session | 0,455 | 0,352 |
| ImageButton, 1 контрол, one-shot | 0,536 | 0,541 |
| ImageButton, 256 контролов, session | 31,75 | 33,42 |

Глубокое наследование ускорилось во всех четырёх парах. Общего ускорения больших
плоских сцен не установлено: диапазоны 256-контрольных процессов перекрываются
(до 28,83–38,55 мс, после 32,68–37,09 мс), медиана после выше примерно на 5%.
На miss кэш дополнительно копирует и оценивает размер сохранённого определения;
этот cold overhead не входит в прогретую строку. В цепочке из 24 компонентов
сохраняются 72 записи с суммарным расчётным весом 457 678 байт. Бюджет можно
уменьшить вплоть до нуля без изменения результата; при этом reuse сокращается.
Числа других проходов не используются как baseline: нагрузка машины менялась.
