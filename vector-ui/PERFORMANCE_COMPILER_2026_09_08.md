# Второй проход 8 сентября: компилятор

CPU sampling (`node --cpu-prof` на compiler-session-bench) выделил
structuredClone, propertyOrigins и GC среди основных затрат. Оптимизированы
трассировка происхождения и повторная проверка контрактов. StructuredClone
сохранён: он обеспечивает изоляцию изменяемой сцены и снимков инспектора.

## Изменения

- Литералы в propertyOrigins возвращают результат без поиска ссылок,
  временного Set и JSON-дедупликации. Для 0–1 источника Map не создаётся.
- При рекурсивном обходе один Set стека переиспользуется с восстановлением
  в finally. Проверены циклы, общая зависимость нескольких ветвей и сохранение
  переданного вызывающим кодом множества.
- Наличие content-slot и набор свойств match вычисляются один раз на связанное
  определение за компиляцию, а не на каждый экземпляр. Метаданные живут в
  локальном WeakMap; постоянный кэш и его лимит не увеличены.
- Подсчёт размера кэша обходит Map и собственные свойства напрямую, без
  временных массивов spread/Object.entries. Это прежняя оценка памяти,
  не новый измеритель JS heap.

Архитектурно ответственность не смешивается: происхождение остаётся в
property-origins, бюджет — в cache-budget, проверка определения — в compiler.
Дублирующая работа убрана без нового глобального состояния и без введения
универсальных классов/DI ради SOLID.

## Скорость

Три пары процессов, порядок AB/BA/AB; в каждом процессе пять выборок после
прогрева. Медиана трёх процессных медиан, миллисекунды на compile.
Первая пара пересекалась с проверками, две последующие — после проверок.
Baseline исходников трёх изменённых модулей получен из HEAD; остальные модули
одинаковые. Сценарии и скрипт одинаковые. До и после сгенерированные source и
шаблон имеют одинаковые SHA-256 во всех запусках.

Проверки: 249 JS-тестов, production build, совпадение выходных хэшей.
