# Forma Studio

## CI и релизы

Библиотека Forma и Studio версионируются отдельно: `forma-vX.Y.Z` и `studio-vX.Y.Z`.
CI проверяет Rust, native-сборки и Studio с настоящим WASM; push релизного тега
публикует проверенный архив после успеха CI. Команды и ограничения —
[RELEASING.md](RELEASING.md).

## Библиотека Forma

`forma` — Rust-библиотека интерфейса; Forma Studio — отдельный редактор.
Приложение подключает библиотеку и использует `forma::Runtime` для загрузки
разметки и обработки состояния интерфейса. Для соседнего checkout репозитория:

```toml
[dependencies]
forma = { path = "../forma/vector-ui" }
```

```rust
use forma::Runtime;
```

`Runtime::from_sources(scene, template)` создаёт runtime из разметки и шаблона
компонента. Нативный demo-бинарник также называется `forma`; самостоятельный
API запуска окна ещё не выделен. WASM-сборка содержит `forma.js` и
`forma_bg.wasm`. Прикладные bindings и подключение обработчиков обсудим отдельно.

Для фиксированной версии будет доступна git-зависимость по тегу `forma-vX.Y.Z`.
Релизных тегов пока нет; в crates.io и npm библиотека пока не опубликована.

## Каталог контролов

Компонентные `.ui` и SVG покрывают кнопки, выбор, поля, диапазоны, навигацию,
дерево, таблицу, сообщения и оболочки. Reveal реализован и проверен в общем
Rust renderer. При `npm run dev` доступен
[каталог Forma](http://127.0.0.1:5173/vector-ui/examples/controls.html)
со светлой/тёмной темой, четырьмя размерами базовых кнопок и экспортом для Studio.
В галерее Rust-модели подключены к выбору, диапазону и дереву; также работают
закрытие вкладок и локальные Select/Dialog/Toast. Native-приложению доступны
те же модели, но экспорт `.ui` пока передаёт визуальный снимок без обработчиков
демонстрационной сессии.

Полный перенос референса ещё не завершён: RTF, сложный shaping/IME reconversion, accessibility,
общие overlays и native window routing требуют дальнейшей работы.
Композиция и запуск — в [документации контролов](vector-ui/controls/README.md),
статус по слоям и полный inventory — в
[карте покрытия](vector-ui/controls/REFERENCE_COVERAGE.md).

## Runtime: несколько контролов

Этап 2б завершён: Frame с несколькими кнопками, независимые hover/focus/click,
переход фокуса клавиатурой и выбор нужной кнопки в дизайнере. Native и WASM
используют общий Rust Runtime; renderer получает геометрию и цветовые слоты.
Пример — `vector-ui/examples/TwoButtons.ui`, при `npm run dev` доступен
[интерактивный стенд](http://127.0.0.1:5173/vector-ui/examples/runtime.html).
Статус, проверки и ограничения — [архитектурные этапы](vector-ui/ARCHITECTURE_STEPS.md).
Свойства и прикладные bindings отложены до отдельного обсуждения. Демонстрационный
хост каталога уже обрабатывает локальное состояние контролов; журнал сохраняется.


## Бенчмарки

`npm run bench -- .forma/perf/my-run` измеряет offscreen throughput, CPU,
Rust-аллокации, RSS, GPU timestamps и объём GPU-ресурсов. Затем
`npm run bench:window -- .forma/perf/my-run` открывает временные окна и измеряет
native present cadence. Методику, ограничения и план оптимизации см. в
[vector-ui/BENCHMARKS.md](vector-ui/BENCHMARKS.md).

## Векторные компоненты

В Forma Studio добавлен режим «Вектор · Rust/WASM». `components/Button.ui` описывает Rectangle, Brush, Border, Text и PointerArea; `ui/VectorButton.ui` задаёт экземпляр. Изменения обоих файлов обновляют canvas прямо в дизайнере. Кнопка «▶ Приложение» в этом режиме передаёт исходную разметку и шаблон native-рендереру, без HTML/WebView. Переходы цветов задаются `transition: 140ms;` в Brush, события передаются через `clicked -> events.clicked();`. Runtime поддерживает один Frame с несколькими контролами, независимыми состояниями и фокусом; визуальное содержимое собирается из вложенных компонентов. Design-данные, ViewModel и прикладной обработчик события ещё не подключены к этому срезу. Подробности и сборка WASM — `vector-ui/README.md`.

## Дизайн-данные из Rust

В `src/design.rs` виртуального проекта экспортируйте `pub const STATUS: &str = "24 документа";` или `pub fn example_query() -> String { "Пример".into() }`. В отдельном дизайн-файле:

```css
design SearchWindow {
    Text { key: 'status'; text: design.STATUS; }
    TextInput { key: 'query'; value: design.example_query(); }
}
```

Нажмите «↻ Данные дизайна» и подтвердите выполнение локального Rust-кода (это не песочница). Результаты кешируются до следующего ручного обновления или перезагрузки IDE. Изменения кода требуют повторного обновления. Ошибки выводятся в диагностике; результат для изменившегося за время вычисления проекта отбрасывается. Поддерживается один автономный `src/design.rs`, стандартная библиотека, константы и функции без аргументов с результатом Display, преобразуемым в текст. Внешние crates, async и методы экземпляров пока не поддерживаются. Сборка ограничена 30 секундами, выполнение — 5 секундами. Временные файлы остаются в системном tmp для диагностики. Дизайн-вызовы не выполняются при запуске приложения.

## Дизайн по key

Любой элемент может иметь необязательный `key: 'status';`, уникальный внутри компонента. В файле, подключённом через `#[design('./SearchWindow.design.ui')]`, можно написать:

```css
design SearchWindow {
    Text { key: 'status';
        text: '24 документа в библиотеке';
        color: #8899aa;
    }
    TextInput { key: 'query'; value: 'Пример запроса'; }
}
```

Свойства заменяются только в режиме дизайна, без изменения исходных привязок и state. В интерактивном режиме и Rust-окне переопределения не применяются. Неизвестные и повторные ключи диагностируются. Старый формат `preview { state: … }` не поддерживается и выдаёт ошибку. Для альтернативных состояний используйте отдельные design-файлы и меняйте ссылку в атрибуте design.

## Запуск Rust

«▶ Приложение» открывает отдельное окно Rust (Tao + Wry, системный WebView) со снимком текущего интерфейса. Ввод query и нажатие поиска связаны с настоящим `actions::search` из текущего `src/actions.rs`. Пока требуется демонстрационный контракт `SearchState { query: String, loading: bool, status: String }`. Это не собственный векторный renderer и не DAP-отладчик. Изменения разметки требуют перезапуска окна. MCP: `app_run`, `app_stop`. Первичная установка зависимостей: `cargo fetch --manifest-path native-app/Cargo.toml`; последующие запуски выполняются offline.

Кнопка «▶ Rust» компилирует и запускает текущие Cargo.toml и src/*.rs через `cargo run --offline` в отдельной временной папке. Вывод и код завершения отображаются в «Событиях». Требуется установленный Cargo. Зависимости должны быть заранее закешированы. MCP: `rust_run`, `rust_stop`. Это реальное выполнение локального Rust-кода, без песочницы приложения. Текущий пример — консольная программа, вызывающая actions::search; нативный renderer разметки и DAP ещё не подключены. Проекты с ресурсами вне src, build.rs и workspace/path-зависимостями пока не поддерживаются. Временные снимки запуска сохраняются в системном tmp для диагностики.

## Подсветка разметки

CodeMirror использует Lezer-грамматику `src/forma.grammar` и палитру `src/forma-highlight.js`. После изменения грамматики выполните `npx lezer-generator src/forma.grammar -o src/forma-parser.js`. Сгенерированные файлы входят в исходники. Подсветка включается для `.ui`, включая дизайн-сценарии; для Rust и Markdown отдельные языки пока не подключены. Грамматика распознаёт предлагаемые `match` и `c(...)`, но их выполнение runtime по-прежнему не реализовано. Runtime пока сохраняет отдельный парсер; объединение парсеров — следующий архитектурный этап.

## Frame grid

Сокращение позиции: `cell: 2 2;` означает `row: 2; column: 2;` (строка, затем колонка, с единицы). Можно сочетать с `row.span`/`column.span`, но нельзя с `row` или `column` в одном элементе. Неверное количество значений, дробные и неположительные координаты диагностируются.

`Frame { columns: [200, *, 2*]; rows: [48, auto, *]; height: 480; gap: 12; }` включает сетку. Количество элементов списка определяет количество явных колонок/строк. Числа и `px` — фиксированные размеры, `%` — процент размера контейнера, `*` — доля оставшегося пространства, `auto` — по содержимому. Для относительной высоты задайте высоту Frame. Переполнение следует правилам CSS Grid (минимальный размер содержимого может ограничивать доли). Если row/column не указаны, дочерний элемент занимает всю явную сетку по соответствующей оси. Несколько таких элементов накладываются друг на друга. Явные размеры элемента сохраняют приоритет над растягиванием. `column: 2; row: 1; column.span: 2; row.span: 1;` задают позицию с единицы и размер области. Без rows/columns Frame сохраняет вертикальный layout. Через MCP редактирование сетки доступно через file_read/file_write. Старая запись fr сохранена как совместимый псевдоним.

## MCP

Запустите `npm run dev` и откройте IDE в браузере. MCP-клиент запускает `node /absolute/path/to/rag/mcp/server.js` через stdio. Пример конфигурации: `mcp/config.example.json`. Подключение к конкретному MCP-хосту выполняется отдельно.

30 инструментов покрывают текущие функции IDE: проект и файлы, активный редактор, компоненты и свойства, сценарии и размеры предпросмотра, состояние, события, диагностику, UI-debugger и запуск Rust. `forma://language` описывает поддержанное подмножество языка. Проверка работающего соединения: `node mcp/smoke.js`.

MCP работает с виртуальным проектом открытой IDE, не с произвольными файлами ОС. Подключается первая вкладка IDE; дополнительная вкладка не перехватывает управление. Требуются запущенный dev-server и открытая вкладка. Production static build не содержит bridge. Локальный bridge использует случайный токен в игнорируемом `.forma/bridge.json` с правами 0600; внешние origins запрещены. `file_write` требует актуальный `expectedContent` при обновлении, `project_replace` — актуальный `expectedFiles`. При timeout результат операции может быть неизвестен: сначала прочитайте состояние, затем решайте, нужен ли повтор.

Локальный прототип IDE для декларативного UI. `npm install`, `npm run dev`; production: `npm run build`; тесты парсера: `npm test`.

Работает: дерево виртуального проекта, текстовый редактор, сохранение в localStorage, импорт/экспорт JSON-проекта, live preview с последней корректной версией при синтаксических ошибках, выбор элемента и переход к исходнику, изменение простых свойств в инспекторе, внешние дизайн-сценарии, просмотр состояния и событий, остановка перед UI-событием и продолжение.

Первая версия языка: component, Column/Row/Panel/Text/TextInput/Button, свойства, прямые state-привязки, отрицание, двусторонний value, события без аргументов, внешний #[design], preview с объектами и массивами.

Ограничения: Rust редактируется как текст и не компилируется; UI-debugger выполняет только демонстрационный actions.search. DAP, синтаксическая подсветка/LSP, полноценный CST, собственные style-блоки, анимации, циклы, выражения и расширения пока не реализованы. Неизвестные компоненты и свойства диагностируются. Проект хранится в браузере, а не записывается в исходную папку ОС. Экспорт создаёт резервную копию проекта. Тема предпросмотра меняет фон поверхности, явно заданные цвета компонентов остаются.

### Инструменты холста Studio

В панели холста доступны режимы «Дизайн / Взаимодействие», масштаб,
«Вписать», «К выделению» и логические размеры. «Размеры» также показывает
расстояния до ближайших соседей по каждой оси и до краёв Frame. Пробел с перетаскиванием
перемещает холст в режиме дизайна; Ctrl/⌘ с колесом меняет масштаб.

«Внутренние части и Grid» раскрывает визуальные примитивы выбранного
экземпляра. Путь над списком позволяет перейти к родительской части.
Двойной щелчок выбирает внутреннюю часть; «К определению»
открывает её исходный файл. Для корневого Frame и Frame внутри компонента можно изменять
списки columns/rows и двигать границы треков мышью либо стрелками
(Shift — шаг 10). Перемещение переводит два соседних трека в фиксированные
размеры; остальные исходные выражения сохраняются. Escape отменяет
незавершённое перетаскивание. Правка шаблона влияет на все его экземпляры.

«Проверка дизайна» подставляет длинный/пустой текст или disabled только
в дизайнере, без сохранения в проект и без изменения нативного запуска.
Для сцен с TableRow доступны отдельные проверки списка: пусто, 12/100 строк,
загрузка и ошибка. Они используют TableRow, Skeleton, EmptyState и Alert
из библиотеки; при отсутствии нужного компонента Studio сообщает об этом.
В этих сценариях редактирование внутренних частей отключено: показанные
строки созданы для проверки, а не записаны в исходник.
Это визуальные проверки, а не модели данных коллекций.

В нативном окне F9 включает инспекцию. Щелчок выбирает контрол без активации,
а Studio получает фактические Frame/Scroll/Control и их границы.
Повторный F9 возвращает обычное взаимодействие. Переход к исходнику
доступен для окна, запущенного из текущей сессии Studio, пока исходный
файл не изменён. Внутренние примитивы шаблона доступны в дизайнере;
нативное дерево пока отражает узлы Runtime на уровне контролов.

В векторном режиме «Дизайн» контролы можно перетаскивать на холсте.
Рамка показывает будущее положение, отпускание мыши создаёт одну правку,
Escape отменяет перенос. В Grid перенос меняет ячейку; в свободной раскладке —
координаты x/y. Стрелки сдвигают на 1, Shift+стрелки — на 10 логических пикселей;
в Grid стрелки переводят в соседнюю ячейку.

Панель редактирования содержит копирование, вырезание, вставку, дублирование,
удаление и Undo/Redo. На холсте работают ⌘/Ctrl+C, X, V, D, Z, Shift+Z и Delete.
Горячие клавиши не перехватывают ввод в редакторе или текстовых полях.
Копирование через клавиатуру помещает разметку контрола в системный буфер;
кнопки копирования и вставки используют буфер Studio. Ключи вставленных
контролов автоматически получают уникальный суффикс. История сохраняется
отдельно для каждого открытого файла. Операции применяются к выбранным
экземплярам; корневые Frame/Scroll защищены от удаления, координаты-выражения
редактируются в коде. Проверочные сценарии и режим «Взаимодействие» не меняют исходник.

«↑ Выше» и «↓ Ниже» переставляют выбранный контрол среди соседей в дереве
и исходнике (Alt+↑ / Alt+↓ на холсте). На границе списка соответствующая кнопка
отключена. Координаты и ячейки сохраняются; автоматическая раскладка следует
новому порядку. Каждая перестановка отменяется одной операцией Undo.


Групповое выделение: Shift+клик добавляет или исключает контрол, рамка мышью
выбирает пересекающиеся элементы, Shift+рамка дополняет выбор, ⌘/Ctrl+A на холсте
выбирает все контролы. Escape отменяет текущий перенос или снимает выделение.
Перемещение, копирование, вырезание, вставка, дублирование и удаление группы
создают одну отменяемую правку. В Grid стрелки сохраняют взаимное расположение
выбранных ячеек и останавливают группу на границе сетки.

Для свободной раскладки доступны выравнивание по краям и центрам общего
выделения (от двух элементов) и равные промежутки по X/Y (от трёх).
Крайние элементы при распределении остаются на месте. В Grid эти команды
отключены: положение задаётся ячейками.

«Привязки» показывает направляющие и притягивает границы/центры группы
к соседям и Frame в пределах шести экранных пикселей. Порог учитывает масштаб.
Alt во время переноса временно отключает привязки. Перенос показывает
будущие границы всех выбранных элементов и изменение координат.
