## 2. Язык `.ui` и компилятор

- [ ] Один источник истины для `.ui`: токенизатор и Rust `form_document`; Studio

  Тест соответствия с манифестом расхождений начат: `test/language-conformance.test.js`
  сверяет компилятор JS и рантайм Rust на 26 значениях свойств раскладки (6 расхождений

- [ ] Типизированный `SceneIr` от `Document` к `Runtime` вместо `serialize_into` и повторного
  разбора (проверено: `SceneIr` в коде ещё нет); текстовый вход остаётся внешним фронтендом.
- [ ] Стабильные идентификаторы узлов: выбор, инспектор и MCP на snapshot и origin,
  reconciliation после редактирования.
- [ ] Реестр свойств и bindings (типы, стили, зависимости, инвалидация): отложен до обсуждения.

## 3. Runtime Forma, оконные хосты и рендер

- [ ] Слияние оконных хостов (проверено: `main.rs` 1861 строка, каталог `native_window` отдельно):
  `main.rs` становится тонким CLI поверх `NativeHost`. Сделано: состояние композиции IME
  общее (`native_window::ImeSession`); общие правила клавиатуры в `native_window/keys.rs`
  (коды активации, обход фокуса по Tab, клавиша в текстовом редакторе); правила модификаторов
  (AltGr, сочетания, перемещение по словам) на `NativeModifiers`; выбор бэкенда в окне выбора (`chooser_pick`); цель IME и положение каретки (`ime_target`, `place_ime_caret`). Осталось: указатель и touch,
  кадр, accessibility, горячая перезагрузка.
- [ ] Сужение публичного API (архитектурный тест слоёв уже строгий: список известных нарушений
  пуст).
- [ ] Иерархическое интерактивное дерево вместо плоского списка контролов с лимитом 256:
  вложенные контейнеры, клиппинг, скролл, hit-test / capture / bubble.
- [ ] Привязка моделей `control_state` к стандартным компонентам на уровне рантайма.
- [ ] Текст и ввод: полный shaping, BiDi, ZWJ и цветные emoji, переносы, fallback; настоящий
  CJK IME, clipboard, accessibility, DPI, несколько окон, вложенные Scroll, физический touch.
- [ ] Стоимость больших форм: per-control snapshots, edit-time rebuild, замеры на
  8/32/96/256 контролах на спокойном хосте.

Рендер (ещё не реализовано):

1. Постоянное дерево UI и раздельные признаки изменения: layout, paint,
   composition. Изменение цвета не должно пересоздавать компонент или layout.
2. Независимый от backend список рисования с bounds, transform, clip-id и
   resource-id. Один и тот же список для CPU, GPU и диагностики Studio.
3. Кэш по элементам/тайлам и dirty rectangles. Сейчас кэш целой растеризуемой
   сцены: scroll перестраивает его, а анимация смешивает всю эту область.
   Вложенные clip временно выделяют полные слои — их нужно ограничить bounds.
4. Общий glyph atlas/кэш SVG и лимит памяти в байтах с LRU-вытеснением.
   Сейчас кэш слоёв принадлежит экземпляру и ограничен одним viewport, но не
   глобальным бюджетом памяти. Большие сцены/глубокие clip всё ещё дороги.
5. Расширение первого GPU-backend через wgpu; CPU остаётся fallback и эталоном.
   wgpu — доступ к GPU, а геометрия, стили и контролы остаются нашими:
   <https://docs.rs/wgpu/latest/wgpu/>

Порядок: дерево/инвалидация → список рисования → локальные кэши → GPU.
Перенос нынешнего полного пересчёта на GPU сам по себе не исправит архитектуру.

## 5. Svet

- [ ] Browser word-input forwarding в `src/vector-preview.js`: настоящий ввод с клавиатуры
  проверен 2026-11-13 в векторном предпросмотре Studio (Chromium, macOS): Option+Backspace,
  Option+стрелка, Option+Shift+стрелка, Option+Delete по выделению и Cmd+Z работают. Не
  проверены IME-композиция, AltGr и не-Apple раскладка Ctrl.
- [ ] Образец `ui/SearchWindow.ui` не открывается в векторном предпросмотре Studio: рантайм
  отвергает `clicked -> state.search()` («'clicked' requires actions.<name>()»), хотя
  HTML-предпросмотр и сгенерированная форма такие действия принимают.
- [ ] Интеграции: transport и realms, async capture после await, SSR/Edge carriers, router
  bursts, другие browser engines; объяснить исторический отказ HTTP external memory.
- [ ] Продуктовые замеры на реальных приложениях: startup, p95, frame time, память.
- [ ] Декомпозиция `compileFormaComponent`, `createCanvas3D` и остатка `gpu.ts` (проверено:
  1423 строки, часть уже вынесена в `gpu-scene3d`, `gpu-sparkline`, `gpu-resident`); слои
  `reactivity` → `dom` → `gpu` → `forma`.
- [ ] JSX-компилятор не должен оборачивать в thunk чистые вызовы (`hasEagerCall`).
- [ ] Убрать дублирование состояния графа между JS и WASM.
- [ ] S-9: байты wasm-ядра зависят от каталога checkout, поэтому побайтовая сверка в CI не
  сходится. Нужно решение: `svet-wasm` в корневой workspace (сейчас исключён по ADR 0001) или
  сверка экспортов и исходников вместо байт.
- [ ] `main.js` только композиция (1929 строк; вынесены отладчик предпросмотра, хранение
  проекта, операции с файлами, модель дерева, панель вывода, снимок раскладки HTML-превью и
  модель панели нативного окна): состояние в `app/state.js`, сервисы
  с портами. Скрытый старый заголовок удалять нельзя, пока нет реестра команд: палитра
  новой оболочки перечисляет его кнопки и нажимает их программно.
- [ ] `components.js` → `compiler/*`, `compile()` по фазам с `CompileContext`; раскладка `src/`
  по фичам.
- [ ] `// @ts-check` послойно: TypeScript не входит в зависимости корня, нужен для проверки.
- [ ] Характеризационные тесты: MCP-команды покрыты целиком (фасад, runtime и проектные на
  100 % строк, дизайн-команды на 96 %); остался экспорт. У компилятора есть корпус ошибок
  (`test/compile-errors.test.js`, 64 случая); набор тестов исполняет все 90 мест `throw` в
  `components.js` (проверено покрытием 2026-11-13), сообщения закреплены не у всех.
- [ ] Свойства корневого `Frame` без сетки компилятор JS не проверяет, а передаёт рантайму Rust,
  и правила двух реализаций расходятся: трёхзначный `padding`, двузначный `gap`, `width: 0`,
  ширина корня выше 4096 (компилятор отвергает её не как размер корня, а потому что контрол
  растягивается на всю ширину и упирается в предел размера контрола) и `clip: true`. Полный список
  в `test/golden/language-conformance.txt`. Ошибки рантайма указывают позицию в сгенерированном
  тексте, а не в исходнике. Решается вместе с единым источником истины для `.ui` (раздел 2).
