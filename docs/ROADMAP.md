# Единый план развития Forma

Открытая работа на 2026-11-13 и её порядок. Выполненное и повторы убраны: пункт стоит в одном
разделе, даже если он упоминался в нескольких прежних планах. Пункты с пометкой «проверено»
сверены с кодом, остальные взяты из прежних планов как есть.

Связанные документы:

- [docs/refactor/PLAN.md](refactor/PLAN.md): статус этапов рефакторинга, решения владельца,
  инварианты, целевая архитектура, проверки.
- [docs/refactor/PLAN_2026_11_12.md](refactor/PLAN_2026_11_12.md): подробный бэклог этапов 0–8 и
  дополнение архитектурного ревью, откуда взяты пункты ниже.
- [packages/svet/PLAN_2026_11_10.md](../packages/svet/PLAN_2026_11_10.md): прежний план Svet с
  точками продолжения и evidence.
- [docs/refactor/BUGS.md](refactor/BUGS.md): журнал дефектов.

- [ ] `forma-build`: линковка `.ui` и кодогенерация типизированных форм целиком на Rust, чтобы
  `cargo build` приложений не требовал Node.js; убрать двойной прогон SVG для поиска `currentColor`.
- [ ] Убрать зависимость `file:../tokenizer/packages/forma` (проверено: ещё в `package.json`):
  версионируемый пакет или проверяемый артефакт. Гейт уже подменяет ссылку на закреплённую
  ревизию, но `npm install` без соседнего каталога не работает.
- [ ] Обновить `wasm-bindgen` с `=0.2.125` (проверено) и вернуть `gpu-compute` и `gpu-kit` в
  корневой workspace, убрав разъезд `wgpu 29` / `wgpu 30`.
- [ ] Зафиксировать продуктовые границы: один рекомендуемый путь приложения на Forma, роль
  `svet-engine`, изоляция вычислительных крейтов.
- [ ] Вывести из эксплуатации WebView-раннер `native-app` после покрытия сценариев через
  `forma::native_window`.

## 2. Язык `.ui` и компилятор

- [ ] Один источник истины для `.ui`: токенизатор и Rust `form_document`; Studio
  (`src/components.js`) и Svet (`forma-ast.ts`, `forma-expr.ts`) переходят на общий AST/IR.
  До этого нужен тест соответствия реализаций с манифестом расхождений.
- [ ] Типизированный `SceneIr` от `Document` к `Runtime` вместо `serialize_into` и повторного
  разбора (проверено: `SceneIr` в коде ещё нет); текстовый вход остаётся внешним фронтендом.
- [ ] Стабильные идентификаторы узлов: выбор, инспектор и MCP на snapshot и origin,
  reconciliation после редактирования.
- [ ] Реестр свойств и bindings (типы, стили, зависимости, инвалидация): отложен до обсуждения.

## 3. Runtime Forma, оконные хосты и рендер

- [ ] Слияние оконных хостов (проверено: `main.rs` 2013 строк, `native_window.rs` 2155):
  `main.rs` становится тонким CLI поверх `NativeHost`. Закрывает F-4 (медленный touch-drag
  исправлен только в `native_window.rs`).
- [ ] Строгий архитектурный тест и сужение публичного API.
- [ ] Иерархическое интерактивное дерево вместо плоского списка контролов с лимитом 256:
  вложенные контейнеры, клиппинг, скролл, hit-test / capture / bubble.
- [ ] Привязка моделей `control_state` к стандартным компонентам на уровне рантайма.
- [ ] Текст и ввод: полный shaping, BiDi, ZWJ и цветные emoji, переносы, fallback; настоящий
  CJK IME, clipboard, accessibility, DPI, несколько окон, вложенные Scroll, физический touch.
- [ ] Стоимость больших форм: per-control snapshots, edit-time rebuild, замеры на
  8/32/96/256 контролах на спокойном хосте.

Рендер (ещё не реализовано):

1. Постоянное дерево UI и раздельные признаки изменения: layout, paint,
   composition. Изменение цвета не должно пересоздавать компонент или layout.
2. Независимый от backend список рисования с bounds, transform, clip-id и
   resource-id. Один и тот же список для CPU, GPU и диагностики Studio.
3. Кэш по элементам/тайлам и dirty rectangles. Сейчас кэш целой растеризуемой
   сцены: scroll перестраивает его, а анимация смешивает всю эту область.
   Вложенные clip временно выделяют полные слои — их нужно ограничить bounds.
4. Общий glyph atlas/кэш SVG и лимит памяти в байтах с LRU-вытеснением.
   Сейчас кэш слоёв принадлежит экземпляру и ограничен одним viewport, но не
   глобальным бюджетом памяти. Большие сцены/глубокие clip всё ещё дороги.
5. Расширение первого GPU-backend через wgpu; CPU остаётся fallback и эталоном.
   wgpu — доступ к GPU, а геометрия, стили и контролы остаются нашими:
   <https://docs.rs/wgpu/latest/wgpu/>

Порядок: дерево/инвалидация → список рисования → локальные кэши → GPU.
Перенос нынешнего полного пересчёта на GPU сам по себе не исправит архитектуру.

## 4. GPU-стек

`gpu-shader`:

- [ ] Декомпозиция на `front/wgsl/*`, `back/msl/*`, типизированная ошибка, `validate_wgsl`.

`gpu-runtime`:

- [ ] `gpu_shader::valid::Validator` не возвращает ошибок (проверено): ill-typed шейдер доходит
  до компилятора Metal. Нужна настоящая проверка типов.
- [ ] `vulkan`, `dx12`, `opengl`, `webgpu`: «reference profile» с обещанными возможностями без
  реализации; оставить только то, что проверяется пробой устройства.
- [ ] Типизированные обёртки вместо `transmute` (проверено: 118 вхождений), `// SAFETY:`
  помодульно, декомпозиция `submit_with_error_sink`, `create_render_pipeline`, `encode_render_pass`.
- [ ] Device loss, смена GPU, forced faults, квалификация signal-driven пути.

Бэкенды (реализации нет, по порядку проверяемости):

- [ ] SPIR-V и Vulkan, проверка в CI на Linux.
- [ ] HLSL и DX12, проверка только на Windows-раннере.
- [ ] GLSL и OpenGL, затем WebGPU.
- [ ] CUDA и RTX только при наличии NVIDIA-хоста.
