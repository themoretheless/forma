## Стоимость больших форм: аллокации и память (2026-11-14)

`cargo run --release -p forma --example multicontrol_perf -- 8 32 96 256`, CPU-растр 640×360 при
масштабе 1.25, контролы рядами по четыре. Время не приводится: средняя нагрузка машины во время
замера была около 370, цифры времени при такой нагрузке недостоверны. Аллокации и байты от
нагрузки не зависят.

|---:|---:|---:|---|---:|---:|
| 8 | 187 | 2 736 480 | 0 аллокаций | 2 445 390 | 3 375 845 |

## Пять проходов по коду дерева контролов (2026-11-18)

Проходы: DRY и SOLID; кеши и горячие пути; асинхронность и конкурентность; DAG модулей;
повторный обзор. Время измерено тестами-замерами в release (минимум из 50–200 повторов) при
средней нагрузке машины 80–110, поэтому важны отношения, а не абсолютные числа.

| Что | До | После |
|---|---:|---:|
| Установка обрезок и областей при загрузке сцены, 1024 контрола без областей | 221 мкс | 4 мкс |
| Перерисовка CPU-растра 800×450, двенадцать обрезанных строк | 332 мкс | 178 мкс |
| `Runtime::set_control_clip` по одному на 1024 контрола (путь превью Studio) | 1,9 мс | 2 мкс |
| Подпись обрезок в превью Studio при отрисовке без перекомпиляции, 1024 контрола | 22–217 мкс | 0 |

`binding_sync_bench`, аллокации и байты на 8 / 32 / 96 контролах: счётчики аллокаций равны
v0.3.8 (692 / 2704 / 8548 без правки, 2004 / 7846 / 23896 на рендер сцены), байты выше на 1–4 %
из-за трёх новых полей `SceneControl` (`clip`, `scroll`, `group`).

Найдено вне оптимизаций: области прокрутки из JSON артефакта и от превью принимались без
проверки (номер области задавал размер таблицы); превью Studio сбрасывало области прокрутки при
каждой перезагрузке сцены. Оба исправлены с тестами.

Конкурентность: `Runtime` остаётся однопоточным (`RefCell`-кеши), новые поля обычные данные;
изменяющие методы берут `&mut self`, поэтому занятый кеш растра или геометрии не может быть
сброшен во время чтения. Асинхронных путей в добавленном коде нет: превью загружает кандидата
синхронно и освобождает его при любой ошибке.
