# Переопределение свойств из файла

В базовом `components/Button.ui` обозначьте цель:

```css
Border {
    key: 'outline';
    width: 1;
    background: #ffffff;
}
```

`styles/AccentBorder.ui` — один элемент того же типа, только свойства:

```css
Border {
    background: Brush {
        color: #bed0ff;
        focus: #ffffff;
        transition: 100ms;
    };
}
```

В `components/SearchButton.ui`:

```css
component SearchButton : Button {
    override 'outline' from '../styles/AccentBorder.ui' {
        width: 2;
    }
}
```

Без локального блока: `override 'outline' from '../styles/AccentBorder.ui';`.
Путь разрешается относительно файла наследника внутри виртуального проекта
Studio. Обращения вне проекта запрещены. Файл не должен объявлять `component`.

Приоритет: базовый элемент → свойства из файла → локальные свойства.
Слияние выполняется по свойствам: значение `background: Brush { … }` заменяет
всю прежнюю кисть, а не отдельные поля внутри неё. Неуказанные свойства,
дочерние элементы и события целевого элемента сохраняются. Изменение key,
добавление детей и событий внутри подключаемого блока не поддерживается.
Тип и единственность цели проверяются при компиляции.

Существующий `override content: match …;` продолжает работать как замена
содержимого ContentPresenter. `from` применяет свойства к элементу по key,
не создавая новую копию элемента. Один key нельзя переопределить дважды
в одном компоненте, но можно переопределить в следующем наследнике.

Studio и запуск native используют общий `compileComponents`; в Rust передаётся
уже раскрытый шаблон. Прямой загрузчик Rust пока не разрешает эти файлы сам.
